# Native x86_64 Support Implementation Plan

> **Scope:** Separate exploratory native-port work. The active user goal is x86-64 PC → QEMU TCG → ARM64 Linux → FKI/XNU → PureDarwin console; this plan is not its acceptance path.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Experiment:** Explore running hosted macOS on Intel and AMD x86_64 Linux PCs through architecture-matched native hosted-XNU modules, while preserving the existing ARM64/macOS 27 runtime.

**Architecture:** Add an x86_64 target alongside ARM64. Keep Linux services shared behind the FKI boundary and isolate architecture state, XNU patches, Mach-O parsing, kexts, and build outputs by target. Start with an execution-boundary milestone and preserve the ARM64 build throughout.

**Tech Stack:** Linux out-of-tree kernel modules, C, x86_64 and AArch64 assembly, XNU source patches, Mach-O/kernel collections, Python build/link tools, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-26-native-x86_64-port-design.md`

## Global Constraints

- Host targets are ARM64 Linux with PAC and 4 KiB pages, Intel x86_64 Linux, and AMD x86_64 Linux.
- Hosted OS targets are the existing ARM64 macOS 27 and x86_64 Tahoe 26.
- Apple system images and binaries are user-provided.
- Intel and AMD runtime support is claimed only after an end-to-end desktop boot on each.
- Software rendering is sufficient for the first x86_64 desktop milestone.
- Architecture and FKI ABI mismatches must be rejected before entering XNU.

## Review Focus

- Foreign code faults while Linux owns the host exception path. Pin recovery and Linux state integrity in Task 1.
- XNU user syscalls enter Linux through x86 syscall machinery. Pin the user-entry routing and verify Linux syscalls still work in Task 2.
- Invalid, truncated, or wrong-architecture Mach-O collections. Pin clean rejection in Task 4.
- ARM and x86 build outputs accidentally mixed. Pin separate build paths and architecture checks in Tasks 3–5.
- Intel/AMD feature differences and unsupported CPUs. Pin feature detection and clear load-time errors in Task 2.
