# x86_64 test-only entry/return contract

## Status and scope

This document defines the evidence required before a test-only x86_64 entry/return implementation may be connected to XNU. It does not add an entry path, change the FKI ABI, or enable execution. The normal x86_64 `xnu.ko` must continue to return `-EOPNOTSUPP`, and the x86_64 FKI backend must continue to report `fki_caps() == 0`.

The disposable-VM boundary probe (PR #71 and its test-only contract extension) validates a Linux-to-Linux call/return boundary. It checks callee-saved GPRs, host-stack bounds, alternate-stack bounds/alignment/canaries, selected RFLAGS, FS/GS/KERNEL_GS, CR0, CR3 root and PCID, CR4, EFER, GDTR/IDTR base and limit, LDTR/TR selectors, preemption/IRQ state, and XCR0 before and after a synthetic assembly call. The ioctl exercises `kernel_fpu_begin_mask(KFPU_387 | KFPU_MXCSR)` and `kernel_fpu_end()` in the calling task. Userspace captures and compares its complete standard-format XSAVE image for all XCR0-enabled user components around the raw ioctl syscall. The probe actively seeds and overwrites x87 ST(0) and its control word, MXCSR, and YMM0–YMM7. Userspace checks that the sentinels appear in its snapshot before the ioctl and restores the original legacy FPU state before returning to C. Other enabled user components have passive image-comparison coverage. It checks Linux syscalls before and after and exercises normal/software-abort returns on each requested online vCPU. The XSAVE comparison does not cover supervisor XSS state or a foreign XNU vector context. This probe does not enter XNU, switch page tables or GS, route exceptions, or validate XNU boot arguments. Its success is necessary host-ABI evidence, not an XNU entry proof.

The contract extension strengthens the existing #71 probe in place with explicit stack, preemption/IRQ, XCR0 and complete enabled-user-XSAVE oracles. It remains a disposable-VM test artifact and does not add a production FKI interface or an XNU transition.

A separate test-only probe in PR #144 has exercised controlled #PF and segment-load #GP recovery on vCPUs 0 and 1 in QEMU TCG. Run [#7](https://github.com/Personed/liXNU/actions/runs/46027708857) verified the expected #GP error code, register/DS/IDTR/stack restoration, post-recovery syscalls, and normal VM power-off. An integrated-branch run [#8](https://github.com/Personed/liXNU/actions/runs/46029449769) reached those kernel and shutdown markers but failed its host-side check because `printk` split a userspace marker; the console adjustment in [PR #157 run #9](https://github.com/Personed/liXNU/actions/runs/46029883909) passed. This remains disposable test-boundary evidence on PR branches, not mainline XNU execution or NMI coverage.

QEMU 8.2.2 TCG writes zero for the x87 instruction and data pointers (FIP/FDP) in XSAVE snapshots. The TCG evidence covers the seeded x87 value and control word, MXCSR, and YMM values. FIP/FDP preservation requires separate evidence. [QEMU TCG XSAVE implementation](https://github.com/qemu/qemu/blob/v8.2.2/target/i386/tcg/fpu_helper.c#L2507-L2533)

## Non-negotiable safety rules

- The first entry-envelope implementation, when its prerequisites are met, must be a separately named test artifact loaded only in a disposable x86_64 Linux VM. It must not be packaged, autoloaded, or enabled by a runtime parameter on normal artifacts.
- The test artifact must assert that `fki_caps() == 0`. Do not define or expose an x86 execution capability until its ABI and every advertised operation have passed the tests below.
- Never treat the parser's `LC_UNIXTHREAD` RIP as an XNU handoff address without confirming the pinned Tahoe entry protocol. Do not map, rebase, apply fixups, allocate executable XNU pages, or jump into an image during this contract's synthetic-entry phase.
- Do not replace Linux's global IDT or production page-fault, general-protection, NMI, or syscall path as part of the synthetic-entry phase. PR #144's disposable test shim temporarily uses its own per-vCPU recovery IDT for controlled #PF/#GP and restores Linux state; this does not establish production XNU exception ownership. NMI injection and any exception recovery during foreign XNU execution still require an independently reviewed per-CPU ownership and rollback design.
- Once a test switches to foreign state, no Linux C callback may run until the Linux stack, flags, task/CPU identity, address-space state, and enabled extended state have been restored. Any failure to prove restoration must abort before a later transition.
- Keep the existing x86_64 `xnu.ko` stub unchanged until its architecture-specific gates pass. This x86 test contract does not edit the ARM64 implementation; its existing behavior and required regression coverage remain in force.

## Test contract

Each row is a separate gate. The harness records the kernel release/configuration, CPU vendor/model/features, vCPU count, artifact hashes, and the furthest passing gate. A failure aborts the sequence and must leave Linux usable; a later gate must not hide an earlier failure.

| Gate | Test-only operation | Required oracle |
| --- | --- | --- |
| Artifact preflight | Read the successful Intel-native Tahoe build artifact without loading it. Run the production parse-only inspector and retain its JSON and SHA-256. | File type, CPU type/subtype, segments, entry-state record, and fixup metadata are reported. Unsupported structure returns an error before any executable-image allocation or mapping; the inspector may allocate an ordinary read-only input buffer. This is structural validation only; the parser does not load or interpret fixups. |
| ABI pinning | Compare the exact artifact and build configuration with the pinned Tahoe source, symbols, entry assembly, boot-argument definitions, and fixup/linker rules. | A reviewed record names the actual XNU handoff symbol/protocol, register and stack inputs, required memory map, and artifact-specific fixup requirements. `LC_UNIXTHREAD` alone is not accepted as proof. |
| Linux boundary baseline | Run the existing #71 probe in a disposable VM before adding new transitions. | The saved host snapshot and its explicit comparisons pass for normal return and software abort; Linux syscalls work before and after; test modules unload; the guest powers off. This baseline does not claim XNU entry. |
| Synthetic entry envelope | Call a test-owned assembly shim on a selected online CPU via `work_on_cpu`, using Linux's current address space and no XNU image. Exercise a normal return and an explicit software-abort return. | Before/after snapshots match for CPU/task identity, task-stack bounds, RSP, relevant RFLAGS, FS/GS/KERNEL_GS, CR0, CR3 root and PCID, CR4, EFER, GDTR/IDTR base and limit, LDTR/TR selectors, preemption/IRQ state, and XCR0. At the shim entry, `RSP % 16 == 8` under the test ABI, and the alternate stack bounds/canaries are valid; the Linux kernel call stack is checked for bounds/equality and natural 8-byte alignment, without assuming a 16-byte kernel-call ABI. Canary GPRs and the calling task's standard XSAVE image match. The calling task's x87 ST(0), x87 control word, MXCSR, and YMM0–YMM7 are actively seeded and overwritten in the ioctl. Other enabled user components have passive image-comparison coverage. The shim's return status is exact and Linux syscalls still work afterward. No C callback executes while the test-owned stack/register state is active. |
| Test-only #PF/#GP recovery | In a disposable VM, inject one controlled #PF and one segment-load #GP into the test-owned shim on each selected vCPU, restoring Linux between cases. | For every selected vCPU, verify #PF vector 14, the expected fault RIP, error code 0, and CR2 equal to the injected guard-page address. Verify #GP vector 13, the expected fault RIP, and exact error code `0xfff8`. The handler's accepted-event counter (`recovery_count`) must equal one per injected vector; after `iretq`, the recovery stub must validate all 15 non-RSP GPRs and RSP separately before reporting success. The handler counter does not count recovery-stub entries. Preserve DS, IDTR, stacks, and canaries; run post-recovery syscalls on the same vCPU; fail closed on nested or unclassified faults. Unload the test modules and power off normally. PR #144 run #7 and PR #157 run #9 passed these test-only checks on two-vCPU QEMU TCG. This does not enter XNU, test NMI, or establish production vector ownership. See the [recovery design](https://github.com/Personed/liXNU/blob/4a3690e79c8a2252a19a85db8b0220cbbcd7e354/docs/x86_64-exception-recovery-design.md#L65-L78). |
| Production exception ownership design | Before entering XNU or injecting an NMI, review per-CPU ownership and recovery alongside Linux vector ownership, nested faults, and unwind. | The design identifies exact handler ownership, entry stack, saved frame, recovery target, and rollback for partial setup. Test-only #PF/#GP handling in PRs #144/#157 does not satisfy this production gate. |
| NMI recovery test | After its separate ownership design is reviewed, inject an NMI into an isolated test-owned shim in a disposable VM. | Record the NMI entry and recovery exactly once on each selected vCPU; preserve Linux state and syscalls, and pass module cleanup and shutdown. NMI is **not run** in the current #PF/#GP probe. |
| Shutdown and cleanup | Exercise normal return, software abort, and each supported recovery path; then unload test modules and power off the guest. | All temporary mappings, stacks, registrations, and per-CPU state are removed. Linux remains responsive until guest shutdown. No case uses the normal service or host boot path. |

The synthetic entry-envelope gate is intentionally narrower than an XNU run. It proves that a future test-only assembly boundary can enter and return from a controlled shim without losing the selected Linux host state. It does not prove the Tahoe ABI, memory isolation, fixups, syscall routing for XNU tasks, exception delivery, or macOS boot.

## Evidence currently missing

These inputs block adapting a test boundary to the XNU image/entry, changing the FKI execution ABI, or making an XNU handoff. The strengthened Linux-only shim supplies additional host-state oracles without the Tahoe artifact, but it does not advance or claim native XNU execution. The concrete handoff prerequisites are:

1. **A successful Intel-native artifact.** The current #56 diagnostics contain no `kernel.development`; there is therefore no artifact hash, file type, image layout, or successful Intel build to inspect. A cross-build on Apple Silicon is useful separately but does not replace this input.
2. **The artifact's real entry ABI.** `docs/x86_64-entry-abi-source-pin.md` records the source-level x86_64 entry protocol for public XNU `xnu-12377.121.6`; the exact artifact still must be tied to its source revision/configuration, memory layout, and CPU setup before use. Do not infer these from the ARM64 `xnu_main.c` handoff or the Mach-O thread-state record.
3. **Artifact-specific fixup/load requirements.** The production parser only validates a bounded subset of Mach-O and chained-fixup metadata. It neither interprets nor applies fixups, and it rejects kernel collections (`MH_FILESET`). Confirm the actual artifact/container format, every required pointer format and page size, and the loader/linker semantics before defining executable mappings.
4. **An x86_64 context contract for FKI.** The execution/state portions of `fki.h` still describe ARM concepts such as PAC keys, AArch64 user registers, and EL0/high-window capabilities. There is no versioned x86 state or transaction ABI for RIP/RSP/RFLAGS, GPRs, FS/GS bases, CR3/PCID, XSAVE, or exception stops. Do not reinterpret ARM fields or add a capability bit to stand in for this contract.
5. **A production exception and syscall ownership design.** The #71 boundary probe and the test-only #144/#157 #PF/#GP harness do not supply a safe recovery path for exceptions during foreign XNU execution or route a hosted XNU task's syscall. NMI recovery remains untested.

Until these inputs are available and the test-only gates pass, the supported behavior is the existing fail-closed refusal. A successful parse or compile does not change that state.

## Current evidence references

- `tests/x86_64/test-boundary-probe-vm.sh` runs the call/return probe only in a disposable Linux VM with QEMU 8.2 or newer for the TCG XSAVE/AVX profile; it never loads XNU. The extension compares the full enabled user XSAVE image around each ioctl and actively verifies restoration of x87, MXCSR, and YMM0–YMM7. Supervisor XSAVE state remains outside this probe.
- The separate test-only [exception recovery module](https://github.com/Personed/liXNU/blob/4a3690e79c8a2252a19a85db8b0220cbbcd7e354/tests/x86_64/exception-recovery/exception_recovery.c) and [serial harness at PR #157 head](https://github.com/Personed/liXNU/blob/a367aafda3bb9d936d640cfbd7bb3a92cc2539fe/tests/x86_64/exception-recovery/test-vm.sh) validate only controlled #PF/#GP handling in a disposable QEMU TCG VM. The successful runs do not exercise NMI or foreign XNU exception delivery; the integrated-run marker failure and console fix are recorded above.
- `tests/x86_64/test-xnu-stub-vm.sh` tests the XNU module's refusal in disposable VMs. Loading this proprietary module taints that guest before its initializer returns.
- `tools/dev/x86_64/xnu-macho-inspect` inspects a candidate artifact read-only; its accepted result does not prove loadability or execution.
- `docs/x86_64-entry-abi-source-pin.md` pins the public x86_64 source entry protocol and its unresolved memory/control-register decisions without authorizing execution.
- `docs/x86_64-native-port-design.md` describes the broader build, memory, exception, and hardware acceptance gates.
